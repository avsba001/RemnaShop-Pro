## 真实运行时修改：写请求不自动重放

旧 `safe_api_request` 默认对所有 HTTP 方法重试，包括遇到网络异常以及
429/500/502/503/504 响应。部分新增动作使用 `retry=False`，但旧创建用户、重置
流量、批量删除等路径仍使用默认值。响应丢失不能证明 Panel 没有执行写操作，
因此外层订单状态保护不足以阻止同一次处理中的 HTTP 层重复写入。

现在统一为：

- GET/HEAD/OPTIONS 在 `retry=True` 时最多尝试三次。
- `retry=False` 的读取只尝试一次，例如 GeoCheck 状态查询。
- POST/PUT/PATCH/DELETE 不论 `retry` 参数值都只尝试一次。
- 已有批量任务层仅对明确允许的安全状态赋值执行持久化重试；重置、删除、
  延期、撤销等不确定写入继续停在 `unknown`，供人工核对。
- 不新增请求字段、不尝试替代路由，不把请求接受状态误报成后台操作完成。

## 验证边界

当前发布源码已移除独立测试代码，保留官方 OpenAPI、契约锁文件和运行时字段校验。
生产仅支持 Docker Compose；容器健康检查不能替代真实面板业务验收。

## 升级与验收

1. 停止机器人服务，通过现有备份工具将配置和 SQLite 卷备份到仓库之外。
2. 确认准备部署的机器人仓库和提交包含本次更新，Panel 使用 3.4.8。
3. 通过原有 Docker Compose 安装/更新入口构建启动；不增加额外服务或新环境变量。
4. 检查日志显示 `V3.8.2` 和 `Remnawave 3.4.8`，容器达到 `healthy`。
5. 另行验证 Panel 认证、订阅列表、测试新购和续费、HWID 设备、Dashboard、
   GeoCheck、批量操作与异常记录。破坏性动作只对专用测试用户执行。
6. 遇到写入结果不确定的订单或任务，先检查面板实际结果，禁止盲目重复审核。

本次不需要额外数据库迁移；保留原有 UUID 证据和数值 ID 绑定策略。
容器 `healthy` 仅表示本地配置和 SQLite 检查通过，不等于外部业务联调成功。
