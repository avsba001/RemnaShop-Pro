# Remnawave Panel 3.4.11 兼容性更新

核对日期：2026-11-15。机器人版本仍为 V3.9.0；本次更新面板兼容目标。

## 版本与来源

Panel / Backend 3.4.11 对应官方 `@remnawave/backend-contract` 3.4.17，取自 3.4.11 标签的 `libs/contract/package.json`。官方发布于 2026-11-14。

仓库保存的是实际下载、声明 `info.version=3.4.11` 的官方 OpenAPI。来源、发布提交及 SHA-256 见 [契约来源](remnawave-contract-source.md) 和 [锁文件](remnawave-contract-lock.json)。

## 与 3.4.8 的完整契约差异

| 项目 | 3.4.8 | 3.4.11 |
|---|---:|---:|
| 路径 | 162 | 162 |
| HTTP 操作 | 218 | 218 |
| Schema | 309 | 309 |
| 变化的 Schema | — | 16 |

- 没有新增或删除路径及 HTTP 操作。
- `GET /api/users/stream` 的可选 `email` 查询参数校验正则变化。机器人按 `telegramId` 查询，不发送该邮箱过滤项。
- 用户创建、修改、批量修改、用户响应、订阅原始响应及 Webhook 中的邮箱正则同步变化。机器人未复制旧邮箱正则，本次不增加一套本地邮箱校验。
- Host 创建、修改、批量修改和响应 DTO 新增字符串数组 `includeInSrrRules`，Host 响应将其列为必填。机器人没有 Host 管理接口，本次不新增此功能。
- OpenAPI 的版本标题和版本号变化。数值用户 ID、内部组数组、新购、续期、HWID、元数据与现有运维操作的路径不变。

## 项目修改

- 更新运行时 `PANEL_TARGET_VERSION`、`PANEL_CONTRACT_VERSION`，启动与错误提示使用新目标版本。
- 替换完整官方 OpenAPI，更新来源、锁文件、49 个直接运行时调用的 API 清单，以及当前 README 和迁移文档。
- 现有创建、修改、批量修改字段白名单和用户响应必填字段仍符合 3.4.11，不为版本号变化重写请求。
- 所有 POST / PUT / PATCH / DELETE 继续禁止 HTTP 层自动重试；写入结果不确定时停留人工核对。

## 验证方法与边界

仅在测试服务器隔离容器中，使用本次源码、官方契约和临时数据库验证：

1. 核对 OpenAPI 版本、文件哈希、路径和 Schema 指纹、官方契约包版本。
2. 遍历实际 HTTP 边界代码的全部直接调用，检查方法、路径及发送的查询参数均存在于新契约；与 49 项清单一致。
3. 检查用户创建、修改、批量修改字段白名单、用户响应和流量响应必填字段与新 Schema 一致。
4. 用 Mock HTTP 验证新购、读取、Telegram 过滤、续期和修改、内部组、元数据、HWID 与批量操作的请求方法、路径和请求体。
5. 验证写请求遇到失败响应或网络异常只尝试一次，读取仍保留有界重试。
6. 运行库存回归检查，确认迁移及购买扣减行为没有退化；检查 Python 语法和 Git 空白错误。

验证脚本按发布约定放在仓库之外，不打入生产镜像。Mock HTTP 验证不等于真实面板联调；本次未向真实面板创建、延期、重置或删除用户，也未操作真实支付。

## 部署验收

本次不修改运行服务，不升级用户的面板，不发布镜像。合并并构建后，使用原有 Docker Compose 流程更新机器人，检查两个服务健康，再对专用测试账号验证开通、续费、内部组及 HWID 等业务。备份和恢复须停止 Bot、HTTP 两个数据库写入服务。
