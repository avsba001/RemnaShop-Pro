# 套餐组合多个内部组

## 使用流程

管理员进入「套餐管理」添加套餐。完成名称、人民币价格、天数、流量和重置策略后，
机器人读取面板全部内部组，提供每页 8 项的多选界面，显示名称和 UUID。
可以跨页选择多个组，保存前必须至少选择一个；保存时再次读取面板确认所有所选组仍存在。
读取失败不会保存空组或偷偷改用默认组。刷新会保留仍存在的选择，并移除面板已删除的组。

已有套餐可从「套餐详情 → 选择内部组」重新设置组合。管理员不需要手工复制 UUID，
也不需要为多个套餐维护全局 UUID 列表。不同套餐可复用同一个组。

例如：套餐 A 选择组 1、组 2，套餐 B 选择组 2、组 3、组 4。
开通 A 的用户被分配组 1 和组 2，不会获得 B 的全部组。

## 数据与兼容

- `plans.group_uuids`：JSON 字符串数组。数据库启动时以新增可空字段迁移，不清空已有数据。
- `NULL` 表示尚未单独配置的旧套餐；新购兼容原来的 `GROUP_UUID`，续费不替换用户组。
- 新套餐必须显式选择非空组列表，格式无效或空列表不能回退到全局组。
- 下单将列表规范化、去重并写入 `payment_intents.snapshot_json`。交付只读取该订单快照，
  不用之后修改的套餐列表或全局默认值覆盖已冻结的显式选择。
- 旧支付快照只含 `group_uuid` 时继续支持；旧续费订单保持原先行为。
- 修改套餐不立即更改现有订阅，只作用于修改后新建的订单。

## Panel 契约

目标仍是 Panel 3.4.8 / backend-contract 3.4.15，以 vendored OpenAPI 为准：

- `GET /api/internal-squads` → `GetInternalSquadsResponseDto.response.internalSquads[]`，
  使用正式字段 `uuid`、`name`。此接口返回完整列表，分页仅发生在 Telegram 菜单。
- `POST /api/users` → `CreateUserBodyDto.activeInternalSquads: string[]`。
- `PATCH /api/users` → `UpdateUserBodyDto.activeInternalSquads: string[]`。

网络访问仍统一经 `services/panel_api.py`；没有新增猜测路由、请求字段或写请求重试。

新购传入全部选中 UUID。显式配置套餐的续费按下单快照**替换**用户内部组列表，
不是与旧权限合并，避免降档续费仍保留高档组。旧套餐及旧快照续费不主动替换组。
续费继续采用现有先 Extend 后 PATCH 的流程；写入结果不确定仍进入人工核对，绝不自动重放。

在下单和交付前校验显式选择的组是否仍存在/可访问。若到账后组被删除，禁止 Panel 写入，
保留已到账记录和失败订单供管理员核对；本功能不自动换组、不退款、不重放失败交付。
管理员应在删除或重构面板组之前先处理关联的未交付订单。

## 验证边界

自动测试覆盖：旧库迁移保留数据、单组兼容、多组冻结、续费权限更新、
组缺失禁止写入、分页跨页勾选、创建最终保存、空选拒绝、重复/失效按钮及管理员权限。
这些是本地自动测试，不代表已完成线上 Telegram/Panel 写入或真实付款验收。

部署仍仅使用 Docker Compose，通过 `bootstrap.sh install --local-source` 更新本地源码快照；
本功能无需额外服务或生产环境裸 Python。实际更新前应按项目既有规则备份数据库，
备份时必须同时停止 Bot 与 HTTP 两个数据库写入方。
